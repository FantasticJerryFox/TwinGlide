# 设置与音频

## 屏幕与键鼠

选择实际连接键盘和鼠标的电脑，再指定另一台电脑在它的左、右、上或下。
点击方向按钮或下拉框均会更新预览。方向始终相对于“键鼠来源”，不会因在哪台电脑打开设置而反转。
当前按每台电脑的完整显示桌面进行连接，不提供单块显示器的旋转角度或任意多屏拼接。

边缘停留可设置 0–1000 毫秒，0 表示立即跨屏；快速返回来源电脑的快捷键固定为
Control + Alt + Shift，加 F10、F11 或 F12。Mac 的 Alt 对应 Option。
这些设置同步到另一端，只有相关输入参数变化才重启双游自己的输入引擎。

两端均固定 Deskflow 1.27，边缘延迟写入 [server]，电脑名称登记到 [computer_名称]；
布局文件只包含 links/options。旧版 section: screens 在 1.27 不再登记电脑。
参照 [Deskflow 设置迁移说明](https://github.com/deskflow/deskflow/wiki/GUI-Settings)。
剪贴板保持关闭。

Mac 初次使用需要本地网络与辅助功能授权，分别用于连接和键鼠控制。
本地网络授权更改后请退出再打开双游；详细步骤见 [Mac 授权说明](MAC_PERMISSIONS.md)。

## 声音

- 各自播放：不采集、不传输另一端声音。
- 选择某台电脑：另一台的系统输出声音加密发送到它，在其默认扬声器／耳机播放。
- 转发音量：0–100%，只调整接收的声音；目标电脑原有程序的音量不变。
- 缓冲：40、80、160 毫秒。这里是缓冲目标，不保证包含网络和设备延迟后的总延迟。

来源端仍保留本地播放。应用不改变系统默认输出、不静音系统，也不安装虚拟声卡。
双向是指可选择任一方向；同一时间只启用一个方向，避免来回录入造成音频循环。
切换目标、音量或缓冲时，旧通道关闭，按新设置建立新通道。
连接中断或取消配对时停止双游自己的音频进程；重连后按已保存设置恢复。
关闭键鼠共享与关闭声音是独立操作。

Windows 使用 [WASAPI 输出回采](https://learn.microsoft.com/en-us/windows/win32/coreaudio/loopback-recording)
与共享模式播放；输出设备更换后会重建连接。Mac 使用
[ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/capturesaudio)
采集系统音频与 AVAudioEngine 播放。仅注册音频输出，不保存屏幕帧，不访问麦克风。
受保护内容、独占音频程序、蓝牙设备及系统授权可能限制采集或增加延迟。
Mac 第一次开启来源端转发时，应允许系统音频／屏幕录制；如果拒绝，可通过菜单栏“系统声音授权”进入系统设置。

音频采用标准库 TLS 1.3 和已保存的双方证书指纹，不带独立共享密码。
网络连接由当前控制会话的发起方建立，音频数据方向由播放目标决定。
控制端口仍为 TCP 59121，不增加音频开放端口。
程序退出仅停止自己启动的辅助程序，不修改旧版桥接服务。

## 通用

设备名称为 1–40 个字符，在发现列表和对方已配对设备中更新。
外观可选浅色、深色、跟随系统。登录自启仅管理当前用户的 TwinGlide 快捷方式或 LaunchAgent，
不会影响其他应用；重新安装会保留已保存的关闭偏好。

名称、外观与自启使用独立保存按钮。切换标签不会丢失尚未保存的修改。
键鼠与声音也各自保存，不会顺带提交另一标签里的草稿。

## 安全测试

--no-input 禁用输入捕获、音频采集、音频播放和自启变更。
--audio-test 在此基础上，仅用本机原生辅助程序生成固定的 48 kHz 双声道样本；
另一端逐样本核验，完全不打开音频设备。该模式用于验证 Windows→Mac 和 Mac→Windows 的
身份校验、格式解析、设置同步、路由切换、重连和停止。合成测试不等于真实采集／播放验收。
