# TwinGlide 双游

**简体中文** · [English](README.en.md)

**一套键鼠，自由跨屏。** 支持 Windows ↔ Mac、Windows ↔ Windows，在两台电脑分别安装，自动发现附近电脑，
两边核对配对码，之后上线自动重连。

TwinGlide 是局域网键鼠共享工具。输入引擎来自
[Deskflow](https://github.com/deskflow/deskflow)，双游提供独立的设备发现、
双端确认配对、身份保存、设置同步和桌面入口。无需账号或云服务。

> **当前阶段：0.1.0-alpha.5，源码预览版。** 本仓库公开源代码与构建脚本，暂不提供公开预编译安装包。Windows alpha.5 与此前本地验证的 Mac alpha.4 使用相同协议。请先查看 [支持与验证范围](#支持与验证范围)；完整记录见 [VALIDATION.md](docs/VALIDATION.md)。

## 工具能做什么

适合桌面上同时使用两台电脑、希望共用一套键盘鼠标，并把系统声音集中到其中一台电脑的用户。

| 功能 | 具体行为 |
| --- | --- |
| 局域网自动发现 | 两边打开软件后显示附近设备的随机昵称；首次生成的昵称会保存，也可手动修改或重新随机生成 |
| 首次确认配对 | 点击设备名，核对两端完整的 12 位十六进制配对码，在两端分别确认后才建立信任 |
| 自动重连 | 保存设备身份，已配对电脑重新上线后自动连接，无需每次重新输入地址或确认 |
| 键鼠跨屏 | 选择键盘鼠标实际连接的电脑；指针越过设定边缘后控制另一台电脑，返回边缘可切回 |
| 屏幕位置 | 设置另一台电脑相对键鼠来源的左、右、上、下位置，并查看双屏预览 |
| 切换偏好 | 边缘停留时间 0–1000 毫秒；紧急返回快捷键可选 F10、F11 或 F12 组合 |
| 系统声音转发 | 选择声音输出电脑，另一台电脑的系统声音通过加密连接转发；可切换方向，同一时间仅一个方向 |
| 独立声音设置 | 接收音量 0–100%，缓冲目标 40／80／160 毫秒，默认关闭转发 |
| 本地个性化 | 设备昵称、浅色／深色／跟随系统外观、当前用户登录自启；窗口关闭后驻留托盘或菜单栏 |

这是原生桌面工具：Windows 使用 WinForms，Mac 使用 AppKit。界面目前以简体中文显示；本仓库提供中英文使用说明，尚未提供英文界面切换。

## 支持与验证范围

| 组合或环境 | 当前状态 |
| --- | --- |
| Windows 10/11 x64 ↔ Intel Mac（macOS 13+） | 已完成两种键鼠来源方向的实体鼠标跨屏、移动、点击及返回；实际系统声音采集、加密传输与接收输出也已双向验证 |
| Windows ↔ Windows | 已实现配对、来源选择和设置同步；协调器测试通过，尚未完成两台实体 Windows 电脑的验收 |
| Apple Silicon Mac | 提供原生构建路径，尚未完成实体设备运行验收 |
| Linux | 仅用于协调器自动测试，目前没有 Linux 桌面客户端或安装包 |

Windows 需要 .NET Framework 4.7.2 或更新版本。Mac 需要本地网络、辅助功能授权；作为声音来源时还需要系统声音／屏幕录制授权。

当前支持**一对电脑**，按每台电脑的完整显示桌面连接；不提供任意多显示器拼接、单屏旋转、剪贴板同步或文件传输。键鼠仅用于已登录桌面，不支持 Windows UAC、锁屏或登录前安全桌面。

全新系统安装／卸载、完整重启／休眠唤醒、地址变更、多显示器及不同缩放比例仍需扩展实机验证。此版本不是经过独立安全审计、商业签名或 macOS 公证的稳定发行版。

## 安装与首次使用

先按 [从源码构建](#从源码构建) 生成对应系统的本地包。下列安装步骤适用于自己构建的包，不表示仓库已有公开安装包。

1. Windows 解压发行包，双击 `Install.cmd`；Mac 解压后打开 `Install.command`。
2. 两台电脑连接同一局域网，并允许安装时的网络访问提示。
3. 打开双游，每台电脑首次启动会获得一个随机昵称，例如“轻快海豚-A7K2”。在“附近的设备”点击另一台电脑的昵称，无需输入 IP。
4. **核对两端显示的 12 位配对码完全一致，在两边分别确认。**
5. 在“屏幕与键鼠”选择键鼠来源、另一台电脑的左／右／上／下位置，可设置边缘停留时间和返回快捷键。
6. Mac 通过菜单栏“本地网络授权”和“辅助功能授权”完成系统授权。更改本地网络授权后，退出并重新打开双游；具体步骤见 [Mac 授权说明](docs/MAC_PERMISSIONS.md)。已配对电脑上线后自动重连。

Windows 使用原生桌面窗口和托盘，Mac 使用原生 AppKit 窗口和菜单栏。没有网页界面，也不依赖浏览器。
Windows 的固定侧栏、统一表单与底部保存区见 [界面设计说明](docs/WINDOWS_UI.md)。
关闭设置窗口不会停止连接，托盘／菜单栏“退出双游”才停止。
临时暂停键鼠可取消“启用共享”。紧急返回键鼠来源电脑默认为 Control + Alt + Shift + F12，可改为 F10／F11。

“声音”按两台电脑的昵称选择输出目标，也可选择各自播放，并独立调整转发音量和 40／80／160 毫秒缓冲。
声音默认不转发；启用后在目标电脑当前的默认扬声器／耳机播放。来源端保留本地播放，不修改系统音量或默认输出，也不采集麦克风。
Mac 作为声音来源时，需要系统音频／屏幕录制授权，可从菜单栏“系统声音授权”打开设置。

“个性化”提供随机昵称／手动改名、浅色／深色／跟随系统外观和登录自启。昵称会保留到下次启动，并同步显示在另一端；外观和自启仅保存于本机。
键鼠和声音设置独立保存；暂停键鼠不会关闭声音，关闭声音请选择“各自播放”。
具体说明见 [设置与音频](docs/SETTINGS.md)。

无法发现时，可展开“高级连接选项”输入另一台电脑的 IPv4 地址；这是排障备用入口。
访客 Wi-Fi、VLAN 和设备隔离可能阻止局域网互访。
首次开放配对 5 分钟；过期可在高级连接选项中重新开放配对。
更换设备身份或清空某一端数据后，需要重新核对配对。

## 屏幕位置与声音的含义

方向始终相对于“键鼠来源”电脑。例如键盘鼠标连接 Windows、Mac 位于右侧，选择 Windows 为来源、另一台在右侧；无论从哪台电脑打开设置，含义都一致。Windows ↔ Mac 首配默认选择 Mac 为来源，Windows ↔ Windows 默认选择发起配对的电脑，之后都可更改。

声音输出目标与键鼠来源独立。例如选择 Mac 作为声音输出，表示 Windows 的系统声音在 Mac 当前默认扬声器／耳机播放。来源电脑仍保留本地播放；双游不会静音系统、改变默认输出、安装虚拟声卡或采集麦克风。同一时间只转发一个方向，防止循环回录。缓冲数值是目标缓冲量，并非端到端延迟承诺。

## 网络与信任

- 自动发现使用 IPv4 局域网广播；不需要账号、云中转或公网端口转发，不提供互联网远程控制。
- 设备名称只是发现线索；配对信任绑定证书身份，两端都确认当前连接的配对码后才保存。
- 控制与音频连接使用 TLS 1.3；后续连接核对已保存的证书 SHA-256 指纹。键鼠数据由启用 TLS 的独立 Deskflow 引擎传输。
- 私钥和配对信息保存在本机用户目录。没有遥测上传或通用远程执行命令接口。
- 网络端口为 UDP 59120（发现）、TCP 59121（控制与音频）、TCP 59122（键鼠）。仅允许需要的局域网访问，不应将这些端口暴露到公网。

实现细节见 [协议说明](docs/PROTOCOL.md) 与 [安全策略](SECURITY.md)。

## 常见问题

| 问题 | 检查与处理 |
| --- | --- |
| 找不到另一台电脑 | 确认两边软件已打开、处于可互通局域网；检查访客 Wi-Fi／VLAN／设备隔离和应用防火墙规则。高级 IP 连接只作为排障备用 |
| 配对超时或只有一边完成 | 两端都重新开放配对，重新连接并核对完整配对码；不要只确认一端 |
| Mac 能被发现但连不上 | 检查“隐私与安全性 → 本地网络”，允许 TwinGlide；更改后退出并重新打开应用 |
| 已连接但无法操作 Mac | 检查辅助功能授权；若列出 TwinGlide Input，也需允许。详见 [Mac 授权说明](docs/MAC_PERMISSIONS.md) |
| 提示已有键鼠共享程序 | 双游会暂停接管。由用户决定是否退出原程序；双游不会自动结束原程序或替换其配置 |
| 声音没有转发 | 确认已选输出电脑并保存、接收音量不为 0；Mac 作为来源需录音授权，受保护或独占音频可能无法捕获 |
| 声音卡顿 | 尝试 80 或 160 毫秒缓冲，检查局域网稳定性及蓝牙设备延迟 |
| 关闭窗口后仍然连接 | 这是托盘／菜单栏运行行为。需要完全停止时选择“退出双游”；暂停键鼠与关闭声音是两个独立操作 |

## 与已有版本共存

双游使用独立的应用名、配置目录、端口、证书和登录启动项。Windows alpha.5 与 Mac alpha.4 使用相同连接协议；双游旧配对身份可以保留。
不导入旧软件的身份，不替换 Deskflow 服务，不终止其他软件进程。音频不复用旧音频服务或其证书。
检测到已有 `deskflow-core` 运行时，会明确暂停键鼠接管；用户自行退出原软件后才能开始共享。

| 内容 | Windows | macOS |
| --- | --- | --- |
| 用户安装 | `%LOCALAPPDATA%/Programs/TwinGlide` | `~/Applications/TwinGlide.app` |
| 私有数据 | `%LOCALAPPDATA%/TwinGlide` | `~/Library/Application Support/TwinGlide` |
| 自启 | 当前用户 Startup/TwinGlide.lnk | org.twinglide.desktop.plist |
| 发现 / 配对 / 键鼠 | UDP 59120 / TCP 59121 / TCP 59122 | 同左 |

卸载使用安装目录中的 `Uninstall.ps1` 或发行包的 `Uninstall.command`。
卸载保留配对数据；需要彻底移除时，先退出应用，再由用户删除上表中自己的私有数据目录。

## 从源码构建

协调器使用 Go 标准库，没有第三方 Go 模块依赖。桌面入口使用系统原生框架。
Go 1.24+；建议使用最新安全补丁版本。构建需要访问官方 Deskflow 下载站。
请先克隆本仓库并进入目录：

```sh
git clone https://github.com/FantasticJerryFox/TwinGlide.git
cd TwinGlide
```

Windows（PowerShell、Go、.NET Framework 编译器）：

```powershell
go test ./...
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-windows.ps1
```

Mac（Xcode Command Line Tools、Go、Python 3）：

```sh
go test -race ./...
python3 scripts/build-mac.py
```

构建只写 `dist/` 和 `engine/cache/`，不会安装应用或激活键鼠共享。
`engine/pins.json` 固定官方输入引擎版本与 SHA-256。
发布包使用完整依赖，终端用户不需要安装 Go、Python 或单独安装 Deskflow。

安全的配对开发模式：

```sh
go run ./cmd/twinglide --data-dir .test-data/device-a --no-input
```

`--no-input` 保证不启动键鼠引擎、输入法辅助进程或真实音频采集／播放，也不改登录启动项。测试必须使用专用数据目录。
需要检查桌面窗口时，运行构建后的应用并设置环境变量 `TWINGLIDE_DATA_DIR` 为专用目录、`TWINGLIDE_TEST_MODE=1`。协调器命令本身没有图形界面。
完整包中的 `--audio-test` 自动启用此保护，仅用原生音频辅助程序生成／核验固定合成数据，验证双向加密传输，不打开真实音频设备。
不要把真实 `identity.pem`、`state.json`、`endpoint.json` 或日志提交 Git。

## 项目结构

- `cmd/twinglide/`：协调器入口。
- `internal/link/`：身份、TLS 配对、局域网发现、重连、引擎管理和仅供本地窗口调用的 API。
- `mac/`：菜单栏／窗口及输入法恢复辅助程序。
- `windows/`：原生 WinForms 设置窗口、托盘、安装、卸载及按程序限定的防火墙规则。
- `assets/`：自制图标的 SVG、PNG 和 ICO；可用 scripts/build-icons.ps1 重新生成位图。
- `scripts/`：独立构建与源码导出。
- `docs/`：协议、安全、测试和发行说明。
